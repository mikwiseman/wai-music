# Hosted Users And Claude Connector

This document describes the current user flow for the hosted `wai-music` service at `https://music.waiwai.is`.

## Current model

`wai-music` uses two separate auth layers:

1. `wai-music` account auth
   This is the web sign-up / sign-in session used for the dashboard and Spotify settings.
2. MCP OAuth for Claude
   This is the connector auth used when Claude connects to `https://music.waiwai.is/mcp`.

These layers are intentionally separate:

- the browser session is for the human user managing their account
- the MCP OAuth token is for the Claude connector acting on behalf of that user

## What users do

### 1. Create a `wai-music` account

Users open `https://music.waiwai.is`, choose `Create account`, and sign in.

### 2. Connect Spotify

From the dashboard, users click `Connect Spotify` and complete Spotify OAuth.

Spotify redirect URI for production:

`https://music.waiwai.is/auth/spotify/callback`

### 3. Add the connector in Claude

For Claude Pro / Max:

1. Open `Customize > Connectors`
2. Click `+`
3. Choose `Add custom connector`
4. Enter:
   - Name: `wai-music`
   - URL: `https://music.waiwai.is/mcp`
5. Leave advanced OAuth client settings empty
6. Click `Add`
7. Click `Connect`

For Claude Team / Enterprise:

1. An owner first adds the custom connector at the organization level
2. Each user then connects it individually from their own connector settings

## Do users need an API key?

No, not for the standard hosted flow.

Users do not need:

- a shared API key
- a manually generated personal token
- a copied access token from the dashboard

The server already supports OAuth-based remote MCP auth, which is the correct model for `claude.ai`.

## Personal access tokens

The dashboard can expose personal access tokens for advanced use cases when the server enables them:

- manual MCP testing with `curl`
- MCP Inspector
- clients that do not support OAuth yet

These tokens are:

- generated per user
- shown only once at creation time
- revocable from the dashboard

They are not the recommended path for Claude. For `claude.ai`, users should use the OAuth connector flow instead.

## What actually happens during auth

When Claude first reaches `https://music.waiwai.is/mcp`:

1. The server returns `401` plus OAuth resource metadata
2. Claude discovers the authorization server automatically
3. Claude registers or identifies itself as an OAuth client
4. Claude redirects the user to `wai-music`
5. The user signs in to `wai-music` if needed
6. The user approves the OAuth request
7. `wai-music` issues OAuth access and refresh tokens to Claude

This means the token is generated by `wai-music` during the OAuth flow. It is not something the user has to generate manually.

## Token separation

`wai-music` holds two different credential types:

- Spotify tokens
  Stored server-side, encrypted at rest, scoped to one `wai-music` user
- MCP OAuth tokens for Claude
  Issued by `wai-music` to Claude, scoped to one `wai-music` user and one connector client

Claude does not receive the Spotify client secret, and users never paste Spotify tokens into Claude.

## Recommended immediate operating model

The current flow is suitable for a controlled rollout or early beta:

- users can sign up
- users can connect Spotify
- users can connect Claude through OAuth

Before broad public launch, the next hardening steps should be:

1. Add email verification
2. Add password reset
3. Add optional invite-only mode or admin approval
4. Add monitoring and audit logging for auth and tool usage
5. Decide whether personal access tokens should stay disabled for the public server

## Summary

The intended `claude.ai` integration model is:

- user account on `wai-music`
- user-scoped Spotify connection on `wai-music`
- user-scoped OAuth connector auth for Claude
- no manual key distribution
- no shared credentials between users
