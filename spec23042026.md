## 1. Описание

### Что делаем

Создать с нуля open-source MCP-сервер `wai-music` — **универсальный программный фундамент для музыкальных AI-продуктов**. Не одноразовый инструмент для одного плейлиста, а публичная библиотека тулов, на которой и автор проекта, и сторонние разработчики могут строить разные продукты.

Основной сценарий использования, вокруг которого проектируется продукт:
- получение "композиции дня" с рассказом про артиста/композитора и про произведение
- поиск музыки по жанру, направлению, годам, сцене, близости
- анализ собственных вкусов пользователя и рекомендации
- универсальность по жанрам: классика, джаз, электроника, рок, хип-хоп, world, поп
- работа через любой MCP-совместимый клиент: Claude Code, claude.ai, ChatGPT connectors

### Принципы дизайна

1. **LLM-first для вкусовой логики, MCP-first для фактов и каталога.**
   Рекомендации, построение нарратива, вкусовые суждения делает host-LLM (Claude/GPT). MCP отвечает за детерминированные вещи: канонические метаданные, биографический контекст, взаимодействие с каталогом и плейлистами. Попытка встроить в MCP similarity-engines или stylistic recommenders — антипаттерн; современные LLM справляются лучше, если им дать факты.

2. **MusicBrainz — canonical spine.**
   После волны deprecation'ов Spotify (ноябрь 2024 → май 2025 → февраль 2026) Spotify больше не может быть источником метаданных. Каждая сущность (artist / release / recording / work) имеет канонический MBID; внешние ID (Spotify URI, Wikidata QID, Discogs ID и т.п.) прикрепляются к MBID через MB relationships.

3. **Backend Protocol для playback-источников с первого дня.**
   Apple Music, Яндекс.Музыка, Deezer, Tidal будут добавляться владельцем вскоре после v0.1. Формальный `PlaybackBackend` Protocol; в v0.1 одна реализация — `SpotifyBackend`. Тулы принимают параметр `backend: str = "spotify"` и обращаются к абстракции. Добавление нового бэкенда не должно требовать изменений в коде тулов.

4. **Stories — hybrid responses (факты + сырой Wikipedia-экстракт).**
   Каждый `get_*_story` возвращает И структурированные `Fact` (даты, события, связи), И сырой `wikipedia_extract` + ссылку. Клиенты разного типа (Claude Code/ChatGPT/сторонний UI) выбирают что использовать. Это критично для расширяемости — сторонние продукты смогут рендерить истории своим способом, не полагаясь на то, что "LLM это сделает".

5. **Универсальность по жанрам из коробки.**
   Режимы "composition of the day" работают одинаково для любого жанра. Curated data-файлы (сцены, must-hear, сезонные теги) покрывают все основные жанры, а не только классику. Первый контентный пример — Рахманинов; это иллюстрация, а не ограничение архитектуры.

6. **Open source с первого дня.**
   Публичный `github.com/mikwiseman/wai-music`, лицензия MIT, CI на GitHub Actions, README с примерами использования, Pydantic-модели экспортируются из `wai_music.models` как публичный API для третьих сторон.

7. **Production-hardening по 2026 MCP best-practices.**
   43% MCP-серверов в аудитах 2025 имели command-injection уязвимости. Входы тулов — только через Pydantic, никогда в shell/SQL без параметризации. Rate-limits соблюдаем (MB требует 1 req/s). Structured logging без секретов. Graceful shutdown.

### MCP tools surface v0.1 (17 тулов)

Все тулы возвращают Pydantic-модели. FastMCP автоматически генерирует JSON Schema из сигнатур. Docstring каждого тула = описание для LLM. Все тулы идемпотентны там, где это имеет смысл.

| #  | Tool                                                     | Назначение |
|----|----------------------------------------------------------|------------|
| 1  | `search(query, type?, limit?)`                           | Поиск artist/release/recording/work через MB, возвращает Entity с MBID |
| 2  | `resolve(identifier)`                                    | Нормализует любой ID/URL (Spotify URI, MBID, Wikidata QID, Genius URL) → Entity со всеми внешними ID |
| 3  | `get_artist(mbid, language?)`                            | MB artist + Spotify match + Wikipedia summary |
| 4  | `get_release(mbid, language?)`                           | MB release + tracklist + Wikipedia + обложка |
| 5  | `get_recording(mbid, language?)`                         | MB recording + Spotify match |
| 6  | `get_work(mbid, language?)`                              | MB work + все известные записи |
| 7  | `get_related(mbid, kind?)`                               | Структурные MB-связи (коллабы, влияния, лейбл-мейты, учителя-ученики). Не AI-рекомендации |
| 8  | `get_artist_story(mbid, angle?, language?)`              | Hybrid: facts + Wikipedia extract |
| 9  | `get_release_story(mbid, language?)`                     | То же для альбома |
| 10 | `get_recording_story(mbid, language?)`                   | То же для трека |
| 11 | `get_scene_story(scene_key, language?)`                  | Story для сцены/движения из curated scenes.json + Wikipedia |
| 12 | `find_track_on(backend, query_or_entity)`                | Найти трек в backend (Spotify v0.1) по Entity или свободному запросу |
| 13 | `create_playlist(backend, name, description, track_ids, public?)` | Создать плейлист в backend |
| 14 | `add_tracks_to_playlist(backend, playlist_id, track_ids)` | Добавить треки |
| 15 | `get_listening_profile(backend, time_range?)`            | Top artists/tracks/saved пользователя + категоризация по жанрам/эпохам |
| 16 | `composition_of_the_day(mode?, date?, language?)`        | Сущность + angle + causing_reason; modes: anniversary / seasonal / scene_dive / chronological / random_curated |
| 17 | `save_notes(slug, markdown, entities?)`                  | Записать `playlists/{YYYY-MM-DD}-{slug}.md` с фронт-маттером |

### Публичные Pydantic-модели (`wai_music.models`)

Стабильный API для третьих сторон. Основные:

- `EntityType` enum: `artist` | `release` | `recording` | `work` | `scene`
- `ExternalIds` (musicbrainz, spotify, wikidata, discogs, genius, open_opus, apple_music, ...)
- `Entity` (type, name, mbid, external_ids, summary, images, primary_date, ...)
- `Fact` (kind: "event" | "relation" | "quote" | "link"; date; label; data; source)
- `Story` (entity_ref, facts, wikipedia_extract, wikipedia_url, language, context_depth)
- `TrackQuery`, `TrackMatch`, `TrackDetails`, `PlaylistRef`, `PlaylistCreationResult`
- `ListeningProfile` (top_artists, top_tracks, saved_count, inferred_eras, inferred_genres)
- `DailyPick` (entity, mode, angle, rationale, suggested_actions)
- `SavedNotes` (path, slug, playlist_ref, entities)

Все — `pydantic.BaseModel`. Экспортируются из `wai_music.models` → сторонние продукты могут импортировать как публичный API без touching внутренностей.

### Транспорты и конфигурация

Один `server.py`, два режима:
- `uv run wai-music` → `stdio` (для Claude Code локально)
- `uv run wai-music --http [--port 8765]` → `streamable-http`, `stateless_http=True`, `json_response=True` (для claude.ai/ChatGPT)

Секреты через `.env`:
```
SPOTIFY_CLIENT_ID=
SPOTIFY_CLIENT_SECRET=
SPOTIFY_REDIRECT_URI=http://127.0.0.1:8888/callback
SPOTIFY_CACHE_PATH=~/.config/wai-music/spotify_token.json

WAI_MUSIC_DB_PATH=~/.config/wai-music/cache.sqlite
WAI_MUSIC_PLAYLISTS_DIR=./playlists
WAI_MUSIC_DEFAULT_LANGUAGE=en

MUSICBRAINZ_USER_AGENT=wai-music/0.1 (+https://github.com/mikwiseman/wai-music)
```

Spotify scopes: `user-library-read`, `user-top-read`, `playlist-modify-private`, `playlist-modify-public`, `user-read-recently-played`.

### Конвенции и безопасность

- Все входы через Pydantic-валидацию. Никогда не строим SQL/shell-команды строковой конкатенацией.
- Секреты только из `os.environ` / `.env` / file (cache_path). Не принимаем секреты через tool-параметры.
- Логирование через structlog, уровень INFO по умолчанию. Никогда не логируем токены, client_secret, полные OAuth-ответы.
- Все внешние HTTP-вызовы через общий `httpx.AsyncClient` с таймаутом 10s, retry с exponential back-off на 429/503.
- MB User-Agent обязателен (политика MB).
- Для публичных плейлистов по умолчанию `public=False`; user может явно передать `True`.
